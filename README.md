# robot-sim-agent

巡检机器人任务执行仿真栈：**自然语言指令 → 结构化巡检计划 → Action 派发 → 状态机执行 → 异常恢复 → Web 实时可视化**。

目标场景是室内设备巡检（配电柜、机柜、水泵房、气体阀组、仪表盘、末端管廊）。整条链路只依赖 Python 标准库 + FastAPI，不需要 ROS 2 环境，所有指标可在本机复现。

> **边界说明（重要）**：本项目是**仿真环境**，不是真机部署。Action 层按 ROS 2 `rclpy` / `action_msgs` 的语义（goal / feedback / result / cancel、终态机）自行实现，全局规划用 A* + 栅格代价膨胀，对照 Nav2 的规划器语义但未使用 Nav2。本体侧（URDF、TF、SLAM、运动学、Gazebo 物理）不在本项目范围内。

## 快速开始

```bash
python -m pip install -r requirements.txt

# 跑一轮任务
python -m rsagent.cli --task "去配电柜A和机柜B看温度，最后回充"

# 起服务（REST + WebSocket）
python -m uvicorn rsagent.service:app --port 8080   # 或见 rsagent/service.py:create_app

# 单测（52 个用例）
python -m pytest tests -q

# 批量评测，产出 bench/out/metrics.json 与 summary.md
python bench/run_bench.py --rounds 40
```

## 几个设计取舍

**1. 模型只产出候选，能不能执行由确定性代码裁决。**
`planner.validate_plan()` 是唯一入口，任何一份计划都要过 Schema、地点白名单、地图指纹三道。未声明的动作类型（比如 `open_door`）一律拒绝，不做「差不多能跑」的兜底 —— 机器人执行错了后果是物理的。校验失败会把原因回灌给模型重生成，重试上限 2 次，用完即失败。

**2. 低电量中断是「一等公民」，不是异常分支。**
执行中电量跌破 25% 会中止当前导航目标 → 回充到 80% → 从断点续跑剩余步骤，进度每步落盘。这样「中断」有明确的恢复路径，而不是靠 catch 一个异常了事。

**3. 读数先过质量门槛，再过告警规则。**
质量不合格（遮挡、反光、超时）的读数返回 `valid=False` 落成 UNKNOWN，**不参与告警判定** —— 拿可疑数字判告警，误报会让人失去对系统的信任。同时 UNKNOWN 触发补测（最多 2 次），否则首帧被判无效会让有效观测窗口从 6 s 缩到 4 s，持续时间类规则（5 s）永远打不出来，表现为「漏报」而不是「读不到」。

**4. 告警不是「越界即报」。**
要求持续超过 `duration_s` 才触发，回落到 `threshold*(1-hysteresis)` 才恢复，同点位同规则只维持一个事件。规则身份是 `sensor+compare+threshold` —— 同传感器可能有多条规则（电压 >250 与 <180 都是 warn），用 `(点位, 传感器, 等级)` 当键会让两条规则互相清掉对方的计时。

**5. 控制权互斥。**
自动任务执行时，手动指令必须显式 takeover 才能下发；接管后原任务 CANCELED 并落盘，恢复时从断点续跑。

## 已知局限

- **没有真机与 ROS 2 运行时**：Action 语义是自实现的，QoS、DDS、TF 树、URDF 都没碰。
- **没有 SLAM**：地图是给定的静态栅格，定位是真值（不模拟漂移与累计误差）。
- **没有真实视觉**：仪表/指示灯读数用数值仿真，不含 OCR、检测模型与相机标定。
- **动态障碍很简单**：只做了栅格级临时占道 + 方向预判减速，没有代价地图与轨迹预测。
- 本地避障用 1 格前向探测近似，真机上是局部规划器（DWA/TEB）的职责。

这些正是从仿真走向真机要补的部分。
